# Go-Live Implementation Plan (Plan 5, milestone M6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** reyancollection.in runs on Railway behind Cloudflare, with:
- real payments, courier, email and media
- a database built by migrations, backed up nightly
- an uptime monitor watching `/api/health`

**Architecture:** The plan has two parts.
- **Part A (Tasks 1–6) needs no accounts.** It makes the app production-ready:
  - a startup check of the env vars
  - media served from R2's own domain
  - migrations applied on boot, and a build that never touches the database
  - `/api/health`, the origin lock and the CSP
  - two order-path fixes
  - a production-mode smoke journey that boots `next start` on an empty, migrated database
- **Part B (Tasks 7–11) needs the accounts.** It deploys, sets up backups, verifies each live adapter (with test keys first), and ends with the launch checklist.

**Tech Stack:** Next.js 16.3.3, Payload 3.92 (Postgres adapter `prodMigrations`), Vitest, Playwright, GitHub Actions (backups), Railway (Railpack builder, `railway.json`), Cloudflare (DNS, proxy, R2, Turnstile, Transform Rules, Email Routing, Web Analytics). No new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-26-reyan-collection-design.md`, mainly §10.1, §10.3, §10.5, §11, §12, §14, §15 and §19.6. Also read "Plan 5 (go-live) must" and every "Plan 5:" line in `docs/superpowers/plans/2026-10-26-00-roadmap.md`.

## What the roadmap got wrong or left out

- **The live Shiprocket adapter exists.** The roadmap says it "still throws", but Plan 4 wrote `src/lib/integrations/shiprocket/live.ts`. All four live adapters (Razorpay, Shiprocket, Resend, Turnstile) exist and are **unverified**. Part B verifies them; it does not rewrite them.
- **There are no migrations at all.** Dev uses Payload's push mode. The first migration covers the whole schema, not only Plan 4's additions.
- **`/api/health` doesn't exist** (spec §10.3).
- **Template leftovers:**
  - `src/app/my-route/route.ts` is a Payload example route.
  - The root `Dockerfile` is the Next example. It needs `output: 'standalone'`, which isn't set, and Railway builds from a root Dockerfile automatically when one exists.
- **`R2_PUBLIC_URL` is documented but never read.** As it stands, production media would be streamed through the app.

## Rulings (approved by Shoaib, 2026-11-24)

- **P5-R1 The build never touches the database.**
  - Railway's private network isn't reachable during a build, and `next build` currently prerenders `/` (and every page under a layout that reads globals) from the database.
  - Fix: the storefront layouts get `export const dynamic = 'force-dynamic'`, the idiom `src/app/sitemap.ts` already uses. Data stays cached by `cached()` and tag revalidation, so a request costs a cache read plus a render.
  - Rejected alternative: pointing the app at Postgres's public URL (billed egress, slower, and a public DB endpoint the app depends on).
- **P5-R2 Migrations apply on boot.**
  - The Postgres adapter's `prodMigrations` runs them on connect when `NODE_ENV === 'production'`.
  - `/api/health` queries the database, so Railway's health check never routes traffic to a deploy whose migration failed.
  - Local dev keeps push mode.
- **P5-R3 Railway builds with Railpack, configured by `railway.json`.** The template `Dockerfile` is deleted. `docker-compose.yml` (local Postgres) stays.
- **P5-R4 Media is served straight from `media.reyancollection.in`,** using `disablePayloadAccessControl` and `generateFileURL`. Product photos are public anyway, and this keeps image traffic off Railway (spec §10.1).
- **P5-R5 Backups go to a separate private bucket, `reyan-backups`, never `reyan-media`.** Everything in `reyan-media` is public through its custom domain, so a database dump there could be downloaded by anyone who guessed its name. This needs a second bucket and token (Task 8).
- **P5-R6 The origin is locked by a shared secret.**
  - A Cloudflare Transform Rule (free plan) adds `x-origin-secret: <ORIGIN_SECRET>` to every request.
  - In production, `src/proxy.ts` returns 403 when the header is missing. The exception is `/api/health`, which Railway calls directly.
  - Only after this check is `cf-connecting-ip` trusted. Without it, a request sent straight to Railway with a forged header bypasses every rate limit.
- **P5-R7 The courier webhook moves to `/api/webhooks/courier`.** Shiprocket's webhook settings reject URLs containing "shiprocket", "kartrocket", "sr" or "kr" (confirm in the panel in Task 10). The route was never deployed, so no redirect is needed. Update spec §8.6 and §10.3 to match.
- **P5-R8 The CSP is a response header, not a nonce.**
  - It is set in `next.config.ts` `headers()` for storefront routes only, not `/admin` and not `/api`.
  - It allows `'unsafe-inline'` scripts (Next's bootstrap and the JSON-LD) and pins every third-party host. `'unsafe-eval'` is allowed only outside production.
  - A nonce CSP would have to reach the Razorpay and Turnstile scripts we inject. That isn't worth it for "basic security headers" (spec §12).
- **P5-R9 `devEmails` stays in production.** `EMAIL_MODE=mock` is the launch-day fallback if Resend misbehaves, and the table is harmless.
- **P5-R10 Not in this plan:**
  - **Vectorising the logo** is design work, not code.
  - **The Plans 1–3 deferred minors** (roadmap) don't block launch at a few orders a day. Two of them can be avoided by policy until fixed: don't create one-use discount codes (two parallel orders can both use one), and don't create a code worth the whole subtotal (Razorpay rejects a ₹0 prepaid order).

## Review Focus

1. **The first deploy on an empty database.** Migrations run on boot, every storefront page renders its empty state (no 500), and `/admin` offers "Create first user". Tested in Task 6.
2. **A wrong env var on Railway stops the deploy at boot,** with a message naming the variable. It must never produce a site that runs and then fails at checkout. Examples: a missing key, an `http://` site URL, `MEDIA_STORAGE` unset. Railway then keeps the previous deploy, because `/api/health` fails. Tested in Tasks 1 and 6.
3. **A request that skips Cloudflare gets 403,** for example one sent straight to the `*.up.railway.app` domain with a forged `cf-connecting-ip`. Railway's health check still passes. Tested in Tasks 4 and 6.
4. **The CSP blocks nothing the shop needs.** The mock-mode e2e suite runs under the CSP (Task 4), and the live hosts are checked in Task 9 with zero console violations.
5. **Courier events without a readable timestamp** (hourly polling) are recorded once, not once an hour. Tested in Task 5.

**Rules:**
- **`originAllowed`:**

- **`storefrontSecurityHeaders`** returns:
  - **CSP:**
    - `default-src 'self'`
    - `script-src 'self' 'unsafe-inline' https://checkout.razorpay.com https://challenges.cloudflare.com https://static.cloudflareinsights.com`, plus `'unsafe-eval'` when not in production
    - `frame-src https://api.razorpay.com https://checkout.razorpay.com https://challenges.cloudflare.com`
    - `connect-src 'self' https://lumberjack.razorpay.com https://cloudflareinsights.com`
    - `img-src 'self' data: blob:`, plus `mediaOrigin` and Razorpay's image CDN
    - `style-src 'self' 'unsafe-inline'`
    - `font-src 'self'`
    - `frame-ancestors 'none'`
    - `form-action 'self'`
    - `base-uri 'self'`
    - `object-src 'none'`
  - **Other headers:** `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` and `Permissions-Policy: camera=(), microphone=(), geolocation=()`.
  - Check Razorpay's and Turnstile's published CSP lists, and add any host they name that is missing here.

### Task 8: Nightly backups to a private bucket

**Files:**
- Create: `.github/workflows/backup.yml`

**Rules:**
- **Trigger:** `schedule` at `30 21 * * *` (03:00 IST), plus `workflow_dispatch`.
- **The dump:** run `pg_dump --format=custom` in a `postgres:<major>` container whose major version matches Railway's server. Upload it with the AWS CLI (R2 S3 endpoint) to `reyan-backups/daily/<YYYY-MM-DD>.dump`.
- **Secrets:** `BACKUP_DATABASE_URL` (Postgres's **public** URL; GitHub can't reach the private one), `R2_BACKUP_ENDPOINT`, `R2_BACKUP_ACCESS_KEY_ID` and `R2_BACKUP_SECRET_ACCESS_KEY`.
