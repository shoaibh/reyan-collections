Spec: `docs/superpowers/specs/2026-10-26-reyan-collection-design.md` (approved 2026-10-26)

v1 is built in five plans, one per milestone. Each plan is written **after the previous one lands**, so it can use the real generated types and file layout instead of guesses. Each plan ends with working, tested software.

## Carried forward from plan 1 (landed 2026-10-26 on branch `plan-1-foundation`)

**Mandatory first task of plan 3 (Ruling R8):**
- `protectVariantStock` (in `src/collections/Products.ts`) currently compares against `originalDoc`. With drafts enabled, `originalDoc` is the **latest version**, which may be a stale draft, not the live main-table row.
- Once checkout decrements main-table variant stock, publishing an old draft with unchanged stock would restore the sold stock.
- Fix: compare against the live main-table stock (`payload.findByID({ draft: false })` or `payload.db.findOne`).
- Test: decrement the main table directly while a stale draft exists, publish the draft unchanged, and expect the decremented stock.

**Deferred minors** (each is small; fix opportunistically in later plans):
- Seed: `seed.int.spec` afterAll duplicates `wipe()`; `upsertAdmin` re-checks env; an existing admin's role isn't reset; media files aren't removed from disk on reseed.
- Tests: media spec asserts only card/og sizes; no anonymous-create-denied test for media; no public-read/admin-update access tests for globals; role default and lockout config untested.
- E2E: an explicit `toPass` timeout; assert env vars instead of `as string`; `dropdb --force` or a comment for `reuseExistingServer`.
- Plan 5: `storage.ts` must throw when `MEDIA_STORAGE=r2` and R2_* are missing; `MEDIA_STORAGE` must be required in production (Railway disk is ephemeral).
- Housekeeping: duplicate `.gitignore` entries; the template description in `package.json`; `NaN` `checkedOn` returns false silently.
- Environment (Shoaib's Mac): the Playwright Chromium cache `~/Library/Caches/ms-playwright/chromium-1208` is broken. Delete it and run `pnpm exec playwright install chromium`.

## Carried forward from plan 2 (landed 2026-10-27 on branch `plan-2-storefront`)

**Plan 3 opening fixes, alongside R8 above:**
- **R17 (open redirect):** `safeUrl` (`src/lib/validators.ts`) and `LinkButton` accept paths like `/\evil.com` or `/\t/evil.com`, which browsers treat as `//evil.com`. Reject `\`, tab, CR and LF in path values, with unit tests.
- **Revalidating stock changes:** checkout's stock decrement (raw SQL on variant rows) must call `revalidate(['products', 'product:<slug>'])` **after the transaction commits**. Payload hooks currently revalidate inside the transaction, before commit.
- **Re-validate the cart server-side:** checkout re-validates stock and price. Cart lines may hold stale quantities or variant ids that no longer exist. Order lines snapshot title, price and variant name.
- **Pickup address:** serviceability must read `pickupAddress` server-side (it is admin-read-only). It currently falls back to the business pincode, or `110001`.

**Plan 2 deferred minors** (each is small):
- Cart: drawer flashes "Loading" on remove and focus drops; focus return fires on navigate; background is not inert; notices are never cleared; no re-clamp on `storage` events.
- Mobile menu: no Escape focus return or outside-click close.
- Search: `%` and `_` act as `like` wildcards; `/shop?category=<unknown>` shows an empty state rather than a 404.
- Product page: DeliveryCheck stale-response race on a fast double submit.
- `/[slug]` `generateMetadata` doesn't early-return for reserved slugs.
- Tests: the seo e2e should assert `og:site_name` and `og:image` values; admin login e2e uses a `toPass` fill retry.
- Dev only: the cold `/admin` compile takes about 30s, because PostCSS runs over Payload's admin CSS. The e2e global setup warms it up.
- `experimental.globalNotFound` (R16): revisit on a Next upgrade.
- Plan 5: a production `next start` revalidation smoke test.

## Carried forward from plan 3 (landed 2026-10-30 on branch `plan-3-checkout`)

**Plan 4 must:**
- **Admin order actions** are Payload collection `endpoints` on `orders` (e.g. `/api/orders/:id/confirm`). Never add Next routes under `/api/orders/...`, because they would shadow Payload's REST.
- **Generalise `cancelPendingOrder`** (`src/lib/commerce/orderOps.ts`) into one cancel that:
  - accepts `awaiting_confirmation`, `confirmed` and `ready_to_ship`
  - releases stock
  - refunds paid prepaid orders (`getRazorpay().refund`, `paymentStatus: refunded`)

  It also cancels the Shiprocket shipment first when one exists. Don't write a second copy.
- **Expiry jobs:**
  - `expirePendingPayments` reuses `cancelPendingOrder` (`pendingPaymentMinutes`).
  - `expireUnconfirmedCod` cancels `awaiting_confirmation` after `codConfirmHours`. Until it exists, an unconfirmed COD order holds stock indefinitely.
- **Admin action buttons** come from `nextStatuses()` in `orderStateMachine.ts`. The Today alerts read `order.alert` (`{ message, handled }`), which is set for "Paid after expiry, refunded".
- **Live Shiprocket adapter.** `getShiprocket()` live mode still throws, so with `SHIPROCKET_MODE=live` every delivery check fails closed and no orders can be placed. This blocks go-live.
- **Stock changes outside Payload** must go through `src/lib/commerce/stock.ts` (`reserveStock`/`releaseStock`). It also syncs the latest product version, so the admin shows live stock.

**Plan 5 (go-live) must:**
- Set `RAZORPAY_MODE`, `TURNSTILE_MODE` and `SHIPROCKET_MODE` on Railway. Production fails closed when any is unset (`src/lib/integrations/mode.ts`).
- Lock the Railway origin to Cloudflare, or stop trusting `cf-connecting-ip` in `src/lib/request.ts`. Otherwise spoofed IPs bypass every rate limit.
- Verify the live Razorpay adapter (orders, refunds, signatures, webhook) and the live Turnstile adapter with test keys. The Turnstile token reset after a rejected order is untested locally.
- Add a CSP that allows Razorpay Checkout and Turnstile (spec §12).
- Check `NEXT_PUBLIC_SERVER_URL` is set before go-live, or fail closed in live mode. Without it `notify.ts` falls back to `''`, so live emails go out with relative "View your order" and "Open in admin" links.
- Write migrations that cover Plan 4's schema:
  - the `dev_emails` collection (consider excluding it in production)
  - the `payload_jobs` tables
  - the order columns `restocked`, `creditNote.*`, `refundNote`, `codBlocklisted` and `shiprocketPickupName`
  - user `name`
  - the unique index on `cod_blocklist.phone`, which the raw-SQL `ON CONFLICT` depends on
  - the `counters` row key `invoice:{FY}` (the spec's `invoiceCounters` collection was not built; the counters row replaces it)
- Verify courier event dedupe against live payloads. When Shiprocket omits a timestamp, `applyCourierEvent` and `pollShipments` fall back to `now`, which defeats dedupe (hourly polling could add an event row per hour). Dedupe on status alone when there is no timestamp.
- Take the COD checkout latency out of the request. `checkout.ts` awaits `notify` twice inline, so a slow Resend could add up to about 20 s. Move the sends after the response, or run the two in parallel.

**Plan 3 deferred minors** (each is small; mostly test hygiene):
- Tests:
  - a few int tests bundle two cases in one `it`
  - the reservation-compensation tests depend on Mint sorting before Sand
  - no test of the 23505 idempotency race path, `loadCommerceSettings` defaults, the live `launchPayment` path, or the double-payment warn log
- `INDIAN_STATES` sort uses the default locale.
- `evaluateCode` throws on unparseable dates.
- `priceCart` trusts the caller to cap `codeDiscount`.
- Discount `usageLimit` and per-phone counts happen outside the order transaction, so two parallel orders can both use a one-use code.
- A zero-total prepaid order (a flat code equal to the subtotal, with free shipping) would be rejected by Razorpay with a 502.
- The blocked-phone COD reason is distinct, so blocklist membership can be probed (low sensitivity).
- The Turnstile reset also fires on field-validation errors.
- `address.state` is stored as typed, not as the canonical name.
