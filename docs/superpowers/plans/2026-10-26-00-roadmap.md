# Reyan Collections v1: Plan Roadmap

Spec: `docs/superpowers/specs/2026-10-26-reyan-collection-design.md` (approved 2026-10-26)

v1 is built in five plans, one per milestone. Each plan is written **after the previous one lands**, so it can use the real generated types and file layout instead of guesses. Each plan ends with working, tested software.

| # | Plan | Spec milestones | Delivers | Status |
|---|---|---|---|---|
| 1 | `2026-10-26-01-foundation-and-content-model.md` | M1 + M2 | Scaffolded app on local Postgres. The full content model (media, users, categories, curated collections, pages, products with variants, homepage/navigation/links/settings globals). Seed data. Branded admin. Admin E2E. | **Written** |
| 2 | `2026-10-27-02-storefront.md` | M3 | Tokens/fonts and the Playful Pop components. Home, `/links`, shop/category/collection, product (variant picker, live stock, delivery check UI on a stub), CMS pages, SEO, on-demand revalidation. | **Done** (branch `plan-2-storefront`) |
| 3 | `…-03-checkout-and-orders.md` | M4 | Orders, discountCodes, codBlocklist, rateLimits, invoiceCounters schema. Pricing/eligibility/state machine (unit-tested). Quote and checkout endpoints, stock reservation, Turnstile, mock Razorpay, the order page and `/track`. | After plan 2 |
| 4 | `…-04-admin-operations.md` | M5 | Today view, order actions panel, WhatsApp confirmation, mock Shiprocket and webhooks, GST invoice PDF, packing slips, jobs (expiry, polling), emails (mock). | After plan 3 |

E2E journeys from spec §16: journey 3 (admin content) starts in plan 1 (admin half) and is completed in plan 2 (storefront half). Journeys 1, 2 and 4 land in plans 3–4.

## Carried forward from plan 1 (landed 2026-10-26 on branch `plan-1-foundation`)

**Mandatory first task of plan 3 (Ruling R8):**
- `protectVariantStock` (in `src/collections/Products.ts`) currently compares against `originalDoc`. With drafts enabled, `originalDoc` is the **latest version**, which may be a stale draft, not the live main-table row.
- Once checkout decrements main-table variant stock, publishing an old draft with unchanged stock would restore the sold stock.
- Fix: compare against the live main-table stock (`payload.findByID({ draft: false })` or `payload.db.findOne`).
- Test: decrement the main table directly while a stale draft exists, publish the draft unchanged, and expect the decremented stock.

**Deferred minors** (each is small; fix opportunistically in later plans):
- Seed: `seed.int.spec` afterAll duplicates `wipe()`; `upsertAdmin` re-checks env; an existing admin's role isn't reset; media files aren't removed from disk on reseed.
- Tests: media spec asserts only card/og sizes; no anonymous-create-denied test for media; no public-read/admin-update access tests for globals; role default and lockout config untested.
- E2E: an explicit `toPass` timeout; assert env vars instead of `as string`; `dropdb --force` or a comment for `reuseExistingServer`.
- Plan 5: `storage.ts` must throw when `MEDIA_STORAGE=r2` and R2_* are missing; `MEDIA_STORAGE` must be required in production (Railway disk is ephemeral).
- Housekeeping: duplicate `.gitignore` entries; the template description in `package.json`; `NaN` `checkedOn` returns false silently.
- Environment (Shoaib's Mac): the Playwright Chromium cache `~/Library/Caches/ms-playwright/chromium-1208` is broken. Delete it and run `pnpm exec playwright install chromium`.

## Carried forward from plan 2 (landed 2026-10-27 on branch `plan-2-storefront`)

**Plan 3 opening fixes, alongside R8 above:**
- **R17 (open redirect):** `safeUrl` (`src/lib/validators.ts`) and `LinkButton` accept paths like `/\evil.com` or `/\t/evil.com`, which browsers treat as `//evil.com`. Reject `\`, tab, CR and LF in path values, with unit tests.
- **Revalidating stock changes:** checkout's stock decrement (raw SQL on variant rows) must call `revalidate(['products', 'product:<slug>'])` **after the transaction commits**. Payload hooks currently revalidate inside the transaction, before commit.
- **Re-validate the cart server-side:** checkout re-validates stock and price. Cart lines may hold stale quantities or variant ids that no longer exist. Order lines snapshot title, price and variant name.
- **Pickup address:** serviceability must read `pickupAddress` server-side (it is admin-read-only). It currently falls back to the business pincode, or `110001`.

**Plan 2 deferred minors** (each is small):
- Cart: drawer flashes "Loading" on remove and focus drops; focus return fires on navigate; background is not inert; notices are never cleared; no re-clamp on `storage` events.
- Mobile menu: no Escape focus return or outside-click close.
- Search: `%` and `_` act as `like` wildcards; `/shop?category=<unknown>` shows an empty state rather than a 404.
- Product page: DeliveryCheck stale-response race on a fast double submit.
- `/[slug]` `generateMetadata` doesn't early-return for reserved slugs.
- Tests: the seo e2e should assert `og:site_name` and `og:image` values; admin login e2e uses a `toPass` fill retry.
- Dev only: the cold `/admin` compile takes about 30s, because PostCSS runs over Payload's admin CSS. The e2e global setup warms it up.
- `experimental.globalNotFound` (R16): revisit on a Next upgrade.
- Plan 5: a production `next start` revalidation smoke test.
